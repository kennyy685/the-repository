# Research round 3 (2026-09-25): a much better home for the AI crew

**FilthE looked at Crew HQ and said it "looks the same as ever."** This round is not about new
features - `crew-hq.html` already does more than it gets credit for (room-aware furniture, live
prop animation on 6+ machines, a waiting/blocked/done/asleep icon system, a "for you" counter). The
gap is that none of it *reads* as alive or urgent at a glance, which is exactly what FilthE (ADHD,
phone-first) needs. 3 scouts looked at agent-hub UIs, cozy-pixel-world techniques, and pixel-art
assets/licensing. Their ideas are merged below into two phases: **Phase 1** tunes the existing
canvas code (no new art, no new data), **Phase 2** adds one small embedded asset and a couple of new
panels. Nothing here touches the database shape, the King chat, the board, or the answer buttons.

**License check done up front:** LimeZu Modern Office is ruled out (its free tier is non-commercial;
HMP is a business). Kenney's Furniture/Robot packs are reported CC0, but the scout's WebFetch to
kenney.nl was blocked this round - **unverified, confirm the license text on the page before
embedding anything from it.**

## Phase 1 - quick wins in the existing code (do these first, no new assets)

1. **Palette pass on decor colors only.** `buildFurniture()` (crew-hq.html:438-556) and `BOOK`
   (:280) scatter one-off hex values (`#34506e`, `#4f81bd`, `#6aa84f`, `#c0504d`, `#e1a63b`, book
   spine colors, etc.) picked ad hoc per prop. Snap those - and only those - to one shared 16-color
   palette so the room reads as one place instead of a pile of unrelated objects. **Do not touch**
   `STATUS` (:281-284) or `LANES` accent/glow (:285-289) - those colors carry meaning (green=working,
   amber=waiting, red=blocked) and are reused by the glow/screen effects; recoloring them breaks the
   "needs you" signal this whole round is meant to strengthen. Suggested palette: **Sweetie-16**
   (GrafxKid, Lospec, CC0) - `#1a1c2c #5d275d #b13e53 #ef7d57 #ffcd75 #a7f070 #38b764 #257179 #29366f
   #3b5dc9 #41a6f6 #73eff7 #f4f4f4 #94b0c2 #566c86 #333c57`. *Flag: lospec.com was blocked for the
   scout this round, so these 16 values are from general knowledge, not opened this session -
   Builder should confirm at lospec.com/palettes/sweetie-16 before locking them in.* Effort: **S/M**.
2. **Drop shadows under furniture.** Bots already get one (:730, a 2-row `rgba(8,10,20,.35)` bar
   under the feet) but desks (`desk()`, :414-426), the couch (:428-434), beanbags (:436), plants
   (:400) and shelves (:401-407) don't. Add one small `shadow(g,cx,fy,w)` helper using that same
   color/alpha and call it once at the start of each placement in `buildFurniture()`. Effort: **S**.
3. **Light / day-night.** Add one flat tint layer in `renderWorld()` (:789-806), drawn after tiles
   and furniture, before bots: dark navy (`#0a1128` @ ~0.32 alpha, multiply-ish) when it's night by
   the visitor's clock (`new Date().getHours()`, before 6am/after 8pm), nothing extra in daytime.
   Skip per-lamp radial gradients and the sine flicker (pixel-worlds scout ranked that its own,
   pricier step) - the existing glow pixels on screens (`drawScreen`, :662-668, already using
   `LANES[lane].glow`) will pop against the darker tint for free. Effort: **S**.
4. **Prop micro-animations, extend what's already there.** `drawFx()` (:669-704) already animates
   the radar, server LEDs, engine flywheel, test monitors and conveyor belt whenever their room is
   active (`act.has(...)`, fed by `activeRooms()` at :659) - that pattern already works, it's just
   not on every room. Add 2-3 more using the same `act.has()` gate: a swaying plant (reuse `plant()`
   at :400, offset by 1px on a slow sine), a ceiling fan or blinking coffee-pot LED in a lounge, a
   blink on the Call Desk's phone/computer bank (:462-464). Effort: **S**.
5. **Floor variety, make it per-room not per-lane.** `floorKind()` (:358) currently only splits by
   x-range (wood = whole chat side, tile = whole code side, carpet = board lane) - every room in a
   lane shares one floor today even though the screenshot suggests otherwise. Switch it to room id:
   Library=wood, Weather=tile, Studio=carpet, Call Desk=tile, both lounges=carpet+rug (rug already
   exists via `rug()`, :435, just extend it under the King's throne too), Engine/Test/Data=tile,
   Ship Dock=hall. Add a 1px baseboard/trim line at each floor-tile-meets-wall row (`drawTiles()`
   already computes a `trim` color at :389 that's currently only used on the wall face, not the
   floor edge - reuse it). Effort: **S**.
6. **Status icons over heads - finish the set.** `icon()` (:868-883) already draws a bobbing `?`
   (waiting, amber), a shaking `!` (blocked, red), a `✓` (done) and rising `z`'s (asleep) - that part
   is done and good. Two gaps: "working" is only a plain pulsing dot (:873-876, by design, to avoid a
   bubble), and true idle (not asleep, not waiting) shows nothing at all. Add a tiny 2-frame spinning
   gear glyph in the same dot's spot for working (keeps it compact, no bubble), and a small dot in
   `STATUS.idle.c` (`#9fb4ff`) for idle so "nothing is happening here" is visible instead of blank.
   Effort: **S**.
7. **A loud "needs you" state - the single highest-payoff item.** The data already exists:
   `openAsks().length` drives the inbox counter (:899-901) and the "N for you" text in the Board
   Room summary (:1012), and waiting bots already get the amber `?`. None of that escalates - it's
   the same visual weight as everything else, so FilthE's own complaint ("looks the same as ever")
   is really "nothing here shouts at me." Add: (a) a persistent banner/pill above the map, only
   rendered when `openAsks().length > 0`, in `STATUS.waiting.c` (`#ffc857`), slow pulse via CSS
   (respect the existing `RM` reduced-motion flag), reading e.g. "3 waiting on you"; (b) make the
   *whole* waiting bot pulse in `drawBot()` (:721-771, tie into the existing `st==='waiting'` branch
   at :751), not just its head icon. Effort: **S** for the banner, **M** if the whole-sprite pulse is
   included.

## Phase 2 - bigger builds (after Phase 1 lands and FilthE has seen it)

A. **A small embedded robot sprite sheet.** Replace the procedurally-drawn rectangles in `drawBot()`
   (:721-771) with a 32x32, 2-4 frame idle sprite sheet for the 3 "main" robots (King, Cowork, Code)
   at least, keeping helper bots code-drawn (cheap, and it visually distinguishes "leads" from
   "helpers" for free). Source: Kenney's CC0 Robot Pack (unverified license this round, see above),
   recolored to the chosen palette, embedded as one base64 `data:` URI near the top of the file -
   never hotlinked, "tens of KB" per the scout's own estimate. Add a feature-flag fallback to the
   current procedural draw in case the asset is missing or fails to decode. Test at phone DPR/zoom.
   Effort: **L**.
B. **A roll-up "Needs You / Working / Done" strip.** A one-screen summary row (columns, not the
   pixel map) above or beside the existing lane tiles, built from data the page already computes for
   `renderSummary()`/`renderChips()` (:1005-1008, :963). This is the "command center" idea from the
   agent-hubs scout (claude-office) - it doesn't replace the map, it's a second, denser view for a
   fast phone glance. Effort: **M**.
C. **Handoff lines on the map.** `drawEnvelopes()` (:782-788) already animates a flying-note handoff
   between agents. Add a faint, short-lived dashed line between the two rooms involved (reuse the
   same `toS()` coordinate helper already used everywhere else) so a handoff reads as a path, not
   just a blip. Effort: **M**.
D. **A visible memory object.** `system/memory` (`facts[]`) already exists and is rendered as a
   plain list by `renderMemory()` (:1082). Give it a body on the map: a notebook or stack near the
   King's throne (`HQ.king` at :319, `{x:416,y:258}`) whose thickness/fill scales with
   `memory.facts.length`, reusing the existing furniture-drawing style. Effort: **M**.

## What NOT to do
- No LimeZu assets (free demo is non-commercial; HMP is a business).
- Nothing from kenney.nl gets embedded until someone opens the page and confirms CC0 in this
  session's context - the scout's fetch was blocked, so it's reported, not verified.
- No runtime image fetches of any kind - any asset must be embedded (base64) in the one HTML file,
  and the file must stay well under 2MB.
- No free-roaming socializing, pets, decorating, health bars, or turning Crew HQ into a game -
  every animation should map to a real state (working/waiting/blocked/done), not flavor for its own
  sake.
- No drag-and-drop workflow builders and no long agent-to-agent chat transcripts rendered on the map
  - that's scope creep away from "what needs FilthE."
- Don't touch the database shape, the King chat, the board, or the answer buttons - none of the
  items above need to, and none should.
- Skip full radial-gradient lamp glow + slow flicker, and skip true tall-wall/y-sort depth, in this
  round - both scouts flagged these as their own bigger, pricier steps; they're good later polish,
  not quick wins.
- Skip dithering (pixel-craft scout: skip for now).
- Don't do a one-shot full repaint of every existing color in the file - `STATUS`/`LANES` colors are
  load-bearing for the "needs you" signal this round is meant to fix; recoloring them is the fastest
  way to make the real problem worse.

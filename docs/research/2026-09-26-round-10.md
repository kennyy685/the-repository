# Research round 10 (2026-09-26): how pro coders use Claude Code - applied to our setup

Sources opened directly this round (official Anthropic docs), not just search summaries - confidence is higher than rounds 5-9.

## Bottom line
1. **Give Claude something that can fail or pass** (a test, a script, a screenshot compare) instead of eyeballing "looks done."
   We have none of that in this repo yet - `tests/` exists but nothing checks app/print output automatically.
2. **Plan mode before multi-file changes; skip it for one-line fixes.** We already work this way loosely; make it explicit.
3. **CLAUDE.md is bloated by pro standards** (it's the shared desk file for 2 AIs, so some length is required) - but it can
   be pruned and split so instructions don't get lost. `/doctor` proposes cuts; we should run it.
4. **We have agents and skills but no hooks, no slash commands, no settings.json.** That's the single biggest gap vs. how
   pro teams run this tool.
5. **Subagents for research/verification, not for grunt work we already do ourselves** - `improvement-scout` fits the
   textbook use (isolated context, reports back a summary); consider one more: a review subagent before shipping print/app
   changes.

## Watch out
- Vendor/blog posts (axify.io, medium, various "2026 guide" sites) repeat the same ideas as the official docs but add
  unverified claims ("50 best practices," specific % savings). Treated as color, not evidence, here.
- `--dangerously-skip-permissions` for CI is real Anthropic guidance but explicitly "only in controlled CI/CD, never on a
  dev machine" - not relevant to HMP's setup (no CI pipeline exists), noted for later if Cowork/Code ever add automated
  tests-on-push.
- Agent teams / `claude agents` background dispatch is called "experimental, disabled by default" in the official docs -
  don't build workflow around it yet.

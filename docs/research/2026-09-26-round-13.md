# Research round 13 (2026-09-26): the Translate feature - built to be number one

Not repeating round 12 (bilingual edge, fixed-vs-AI-text rule, glossary idea) - this round designs the actual feature.

## Bottom line
1. **Nobody builds a translator for a door-to-door insurance-restoration sale.** Google/Microsoft/Apple/Pocketalk/SayHi
   all target tourists, meetings or classrooms - none has a fixed legal-glossary mode or a "read this exact notice aloud"
   mode. That gap is winnable with a small, disciplined build, not a big one.
2. **The single biggest technical risk is the claude.ai artifact webview, not the language model.** `SpeechRecognition`
   (mic-in) is flaky-to-broken inside app webviews on iOS even though it works in real Safari [4]; `speechSynthesis`
   (read-aloud) on iOS Safari can't reliably pick a Spanish voice via the API - the good "Jorge" voice exists on the
   phone but isn't exposed to `getVoices()` [7]. **Test this in the actual Claude app webview before designing around it**
   - if recognition doesn't fire, the feature becomes type/tap-to-translate + read-aloud only, not voice-in.
3. **Every named live-translation product (Google Live Translate, Microsoft Translator, Pocketalk) is converging on the
   same UX**: one phone, flip/split screen, auto language-detection per turn, big flipped text for the other person to
   read, tap-to-replay audio. That's the pattern to copy, not invent.
4. **Legal text must never be re-translated live** - this repeats and hardens round 12's rule with fresh sources: AI
   translation quality is good for chat, unproven/risky for anything binding [confirmed again, same finding as round 12].

## The UX pattern to copy (from the products, cross-checked)
- **One phone, on the table, screen split top/bottom** - Microsoft Translator's split-screen literally flips the top
  half's text so the other person reads it right-side up without picking up the phone [1]. Google's Conversation mode
  and Pocketalk both auto-detect which language is being spoken each turn, no repeated tapping [source 1 search summary].
- **Push-to-talk beats always-listening outdoors.** Dedicated devices (Pocketalk) use a physical button specifically
  because open-mic in noise causes false starts and mixed-language picks up cross-talk [3, summary]. For a phone app,
  that means: **one big button, hold to talk, release to translate** - not a hot-mic mode - for the door-to-door case.
- **Big flip-to-show text, not just audio** - useful when the porch is loud, when the homeowner is hard of hearing, or
  when precise terms (a claim number, an address) need to be read, not just heard.
- **Auto-playback toggle, not buried in settings** - Google just moved this to a direct button because it was hidden
  before [1] - lesson: put "speak it out loud" as one visible tap, not two menus deep.
- **Noise handling**: dedicated hardware wins on raw fidelity (dual mics, no OS throttling) [3] - HMP will use a phone,
  so the practical fix is UI, not hardware: large glossary-term chips so a common exchange ("can I see your roof",
  "when did the hail hit") doesn't depend on noisy mic pickup at all.

## Concrete feature spec: "Translate" in the HMP App

### Mode 1 - Door conversation mode (FilthE + homeowner)
- One phone, held between both people or set on a rail/porch table.
- **Hold-to-talk button**, language auto-set by who's talking is too failure-prone per source [4]; instead **two
  buttons side by side, labeled "I speak" (EN) and "Habla" (ES)** - FilthE picks which button before each turn. Simpler,
  more reliable than auto-detect on a phone webview, and matches how a rep actually works a door (he knows who's about
  to talk).
- Speech-to-text of that turn -> Claude translates -> **big text shown flipped for the homeowner's side** + optional
  read-aloud (auto-play toggle, on by default, one tap to mute).
- **A visible glossary bar above the input**: tapping a term (see glossary below) inserts the fixed bilingual phrase
  instead of asking the model to translate it fresh - guarantees "deducible," "ajustador," "depreciación" never drift.
- **"Say it again simpler" button**: re-sends the last AI translation back through Claude with an instruction to use
  shorter, plainer words in the same language - for when the homeowner looks confused. Does not touch legal text (that's
  read-aloud only, see Mode 2).
- **Quality check - back-translation on demand**: a small "check" icon translates the AI's Spanish (or English) back to
  the original language and shows both side by side, so FilthE can eyeball whether the meaning held - standard practice
  in legal-translation QA [round 12, source 3] adapted here as a manual spot-check, not automatic (would slow the walk).
- Fallback if mic input doesn't work in the webview: type-to-translate box, same output side (flip text + read-aloud).
  **Verify in Claude's iOS webview before building voice-in** - budget a 30-minute spike first.

### Mode 2 - Fixed legal text, read aloud (never AI-generated)
- A short list of pre-verified fixed strings only: the 3-day cancel notice, the 44-8607 deductible notice (5-sentence
  version, per CLAUDE.md's 2026-09-26 verification), the door-opener line (name / HMP / what we sell, per 69-1602).
- Each has a stored English string and a stored Spanish string (typed once, FilthE read-back checked, never touched by
  the translation model again). The Translate feature's only job here is **text-to-speech playback** of that exact
  stored string, at a slow/clear rate, with a "play again" button - not translation.
- This directly satisfies 69-1604(3) (notice given in English AND Spanish) with a tool, not just paper.

### Mode 3 - Crew-instructions mode (the boss's Spanish-speaking crews)
- A second, separate glossary: job-site task words and safety words (tear-off, flashing, furring, "watch the edge,"
  "tie off," "hail damage," measurements) - different vocabulary from the sales glossary, so keep it a separate list
  the boss's foreman opens, not mixed into the homeowner-facing one.
- Same hold-to-talk + flip-text pattern, but no legal content and no "back-translation" step needed (lower stakes,
  faster back-and-forth wanted).

### The glossary (fixed EN/ES pairs, forced into every AI translation call so terms never drift)
Roofing/siding: roof, techo; shingle, teja/tégula (Mexico often says "teja asfáltica"); flashing, tapajuntas/contra-
techo; underlayment, membrana; gutter, canaleta/canalón; soffit, sofito; fascia, fascia; furring strip, listón;
siding, revestimiento/siding (siding is widely used as a loanword in Mexican Spanish - keep both); hail, granizo;
wind damage, daño por viento.
Insurance/claims: adjuster, ajustador (also "perito" in some countries - use "ajustador" as HMP's standard, it's the
term used across US Spanish-language insurance material [source 5]); claim, reclamo; claim number, número de reclamo;
deductible, deducible (never say "cubrir," "eliminar" or "rebajar" the deducible near this word - that phrasing itself
risks sounding like an offer to waive it); depreciation, depreciación; ACV (actual cash value), valor real en efectivo;
RCV (replacement cost value), costo de reemplazo; supplement, suplemento; scope of work, alcance del trabajo;
inspection, inspección; estimate, estimado; contract, contrato; cancellation, cancelación; registered contractor,
contratista registrado (never "licenciado" - matches the hard rule to say "registered," not "licensed").
General: homeowner, propietario/dueño de casa; free inspection, inspección gratis; no obligation, sin compromiso.
**Regional note (partly unverified this round):** confirmed sources show Mexico favors "lámina" for metal roofing and
uses "siding"/"revestimiento" interchangeably [source 6]; Central American Spanish (Guatemala/Honduras) shares more
vocabulary with each other than with Mexican Spanish on general words [source 7, 8], but **no source this round
compared insurance-specific terms (ajustador/deducible/etc.) Mexico vs. Central America directly** - flagged unproven;
if HMP's homeowner base is mixed-origin, the safest fix is to keep the fixed glossary in the most widely-understood
form (as listed above) and let FilthE (bilingual) confirm live if a homeowner uses a different regional word.

## Ranked build list
1. **30-minute spike: test SpeechRecognition + speechSynthesis inside the actual Claude/HMP-App webview on an iPhone** -
   everything else depends on the answer. Who: Code. Effort: S.
2. **Mode 2 (fixed legal read-aloud)** - lowest risk (no live AI translation), directly meets a legal requirement
   already on the books (69-1604(3)), reuses text already verified in CLAUDE.md. Who: Code + FilthE (read-back check).
   Effort: S.
3. **Glossary data file (EN/ES sales terms) wired into any AI translation call**, reused by Mode 1 and Mode 3. Who:
   Code. Effort: S.
4. **Mode 1 door conversation mode** (hold-to-talk per speaker, flip text, auto-play toggle, "say it again simpler").
   Who: Builder + Code. Effort: M.
5. **Back-translation check icon** - small add-on to Mode 1 once it exists. Who: Code. Effort: S.
6. **Mode 3 crew-instructions glossary + mode** - lower priority than the sales-facing feature since FilthE, not the
   crews, drives app adoption right now; do after Mode 1 ships and FilthE has used it on real doors. Who: Builder.
   Effort: S.

## Watch out
- Never let the AI translation layer touch deductible language beyond the fixed glossary word "deducible" itself -
  no AI-generated sentence about the deductible, ever; that's Mode 2's job only (44-8604).
- Don't build voice-in before confirming the webview works - a silently-broken mic is worse than no mic (FilthE will
  think it's his phone, not the platform).
- Don't chase "70+ languages" - HMP needs EN/ES well, not breadth.
- Regional Spanish word choice for insurance terms is genuinely under-sourced; treat the glossary above as a strong
  starting draft FilthE should sanity-check against real conversations, not a finished linguistic authority.

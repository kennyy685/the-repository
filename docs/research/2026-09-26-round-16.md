# Research round 16 (2026-09-26)

FilthE's vision: open the phone, see hot zones on a map, drive there, get told which doors are
likely-insured and worth knocking. Three questions this round: (1) free legal proxies for "is this
house insured," (2) can an artifact page show a real map, (3) what SPOTIO/SalesRabbit/HailTrace/Roofr
actually use for hot-zone + door scoring, so we can copy the free parts.

## Summary
- **No source (free or paid) says "insured: yes/no" per house.** Everyone proxies it. The honest
  proxy stack: owner-occupied (mailing address = situs address) + has a mortgage (lender requires
  insurance) + not vacant/bank-owned + residential class. National baseline: ~86-90% of
  owner-occupied homes carry insurance; recent Census data puts ~55-61% of owner-occupied homes with
  a mortgage (39.4% owned free-and-clear in 2020-2024, up from 34.4% a decade earlier) [1][2].
- **Nebraska's statewide parcel layer (the one `hailhunter/parcels.py` already pulls) has no owner
  name or owner-mailing-address field** - `FIELDS` is Situs_Address, BuildingYear, Classification_Code,
  Property_Parcel_Type/Status, ImpSF, Improvements_Value, Total_Assessed_Value, Sales_Date,
  Subdivision, GIS_Acres, etc. [checked against `hailhunter/parcels.py:18`]. So "owner mailing ==
  property address" can't be computed from this feed alone - it needs county assessor data that
  carries owner mailing address (some county assessor sites/GIS layers do, statewide layer doesn't).
  This is a bigger gap than T23's note ("owner-occupied is per neighborhood, not per house") already
  flags - worth a scoped follow-up scout per county before building it.
- Nebraska has **no state-level bulk Register of Deeds feed**; it's per-county (some via
  nebraskadeedsonline.us, some standalone) [3] - too much per-house work for free/manual use now.
  `Sales_Date` in the parcel feed is already a decent free stand-in for "recent sale = likely has a
  new mortgage."
- **Claude artifact pages cannot load external map tiles** - the CSP is `connect-src 'self'` /
  `frame-src 'self'`, so no OpenStreetMap/CARTO/Esri/Stadia tile calls, no external tile images
  [4]. Leaflet/MapLibre *libraries* from cdnjs/jsdelivr would load fine, but there is nothing for
  them to fetch tiles from. The workable options are (a) inline vector-only SVG map from our own
  GeoJSON (block-group polygons + streets, colored by heat, no basemap) - matches what the
  `artifact-capabilities`/`artifact-design` pattern already supports, or (b) a static PNG "hot zone"
  image we render server-side (matplotlib, already a dependency) and embed as a data URI, refreshed
  each `hh.py refresh`. Either way, add `maps.apple.com/?daddr=` / `google.com/maps/dir/?api=1&destination=`
  links per address for turn-by-turn - those open the phone's own map app and work from any page,
  no CSP issue.
- **SPOTIO/SalesRabbit/RepCard/HailTrace/Hail Recon/Roofr** hot-zone + door-ranking, in order of what
  we can copy free: hail swath overlays (we already have, MRMS-based, arguably better since it's
  calibrated to local ground reports) > home age/value/owner-occupied flags (assessor data, same as
  us) > "credit capacity / income / buyer propensity" models from 1,700+ third-party variables
  (SalesRabbit's DataGrid AI) - this is paid consumer-data enrichment we should NOT chase: cost,
  creepiness, and likely brushes against using non-property data to target a homeowner door-to-door,
  which isn't illegal but isn't HMP's lane or budget [5][6].

## Door score v2 recipe (concrete)
`door_score = hail_score x recency x distance x roof_age_factor x building_type x likely_insured x sold_after_storm_flag`
where `likely_insured` (new factor, 0.5-1.0, replaces a flat multiplier) =
- 1.0 if: owner-occupied neighborhood flag (existing) AND `Property_Parcel_Type` = single-family
  residential AND `Sales_Date` within last 10 years (proxy for an active mortgage) AND not flagged
  vacant/tax-delinquent.
- 0.7 if owner-occupied but no recent sale (older mortgage-free owner - still ~86% national
  insured rate, just lower "has a lender checking" pressure).
- 0.4 if renter-occupied or unknown (landlord's policy, not the resident's decision - lower doorstep
  fit for HMP's homeowner-direct pitch).
Data sources to add: Nebraska statewide parcel layer (`hailhunter/parcels.py`, already pulled) for
`Sales_Date`, `Property_Parcel_Type`, `Classification_Code`; existing Census block-group
owner-occupied share (already in `nbhd`) stays the per-neighborhood fallback until a per-house
source is found (see D17 above).

## For FilthE (plain lines)
- No website tells us "this house has insurance" - not us, not SalesRabbit, not anyone. Everyone
  guesses from the same public clues: does the owner live there, did they buy recently (probably
  still paying a mortgage, so the bank requires insurance), is it a regular house not a rental.
- Your Nebraska statewide land records don't include the owner's mailing address, so "owner lives
  there" is still a neighborhood-level guess, not a per-house fact yet - that's a real gap to close,
  not something already solved.
- A real scrolling map with streets (like Google Maps) can't load inside these claude.ai pages - the
  workaround is a picture of the hot zones (still useful, just not scrollable/zoomable) plus one-tap
  "get directions" links that open your phone's normal map app.
- The paid tools (SalesRabbit etc.) buy expensive third-party credit/income data to guess who'll buy
  - not worth it for HMP's size; our free hail + property data does the same job for the real
  bottleneck (hail accuracy + owner-occupied), which we already have.

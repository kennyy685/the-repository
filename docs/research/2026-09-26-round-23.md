# Research round 23 - Wind/fallen-tree claims + Commercial/apartment roofs

**Summary:** Wind claims are a real, mostly-untapped second lead source that rides on data the engine
already pulls (`wind_obs` -> hud.json `wind_events`) but never scores or shows on a map. Commercial/
apartment roofing (TPO/EPDM) is a slower, relationship-and-paperwork sale (property manager budget
cycles, RFPs, references) - not a knock-and-close product like residential hail. Both topics end in
concrete, buildable next steps.

## What to work on next (ranked)

1. **Score and show wind zones on the hot-zone map, same as hail** - Effort: M, Owner: Code
   (engine-mechanic) then Builder for map display.
   Use the engine's own `wind_obs`/`wind_events` data. Suggested exact factors (mirrors the hail
   scoring shape in CLAUDE.md so it's a drop-in, not a new system):
   - **Severity factor** (gust speed, matches NWS's own severe-thunderstorm threshold already used in
     `hud.py`'s 58 mph filter): <58 mph = 0 (not scored, matches current filter), 58-64 = 0.35,
     65-74 = 0.65, 75-89 = 0.85, 90+ = 1.0. [1][2] This lines up with the damage bands multiple
     roofing sources report: 58-74 mph tears off intact shingles and starts uprooting trees; 75+ can
     strip large sections regardless of roof age/condition. [1][2]
   - **Recency and distance factors:** reuse the existing hail decay curves unchanged (full to 45
     days / 0.4 at 1 yr; full to 30 mi) - no new code path needed, same shape of storm.
   - **Directional slope weighting (new idea worth a second pass):** several sources note wind damage
     is one-sided - "most damaging wind comes out of the west/southwest, so those slopes take the
     beating while sheltered slopes are untouched" - unlike hail which hits evenly. [3] This means a
     wind-zone door list should flag which house wall/roof slope faces the reported wind direction if
     LSR/wind_obs records a direction; if it doesn't already, that's a small ingest addition
     (`engine-mechanic`) worth checking.
   - Don't blend wind into the single hail-based house score - keep it a **separate wind score** and
     a second map layer/list, since wind claims are usually partial-roof, not whole-roof, and the
     sales pitch and inspection are different (see #3 below).

2. **Add a fallen-tree damage lead trigger** - Effort: S, Owner: Code.
   No new data source needed if wind reports already carry `report_kind` - the LSR wind_obs table
   HMP already ingests includes NWS "TREES DOWN" / "TREE DAMAGE" storm reports alongside gust
   readings (same Iowa Mesonet LSR feed the engine already reads for hail). Surface any tree-down LSR
   inside HMP's normal radius on the same map layer as wind zones with its own icon/label - this is a
   free, already-collected pointer to addresses worth a door knock ("did the storm knock a tree onto
   your roof?"). Verify the LSR feed carries tree reports before building (untested assumption -
   flag to confirm with `engine-mechanic` by checking a sample LSR pull).

3. **One-page wind/tree inspection + sales playbook for FilthE** - Effort: S, Owner: FilthE + Code
   (write it once it's asked for, like the adjuster-meeting checklist from round 22).
   Key differences from hail he needs to know before his first wind claim:
   - Wind damage looks different: creased tabs, shingles lifted at the edge or missing entirely along
     ridgelines/rakes/edges - not the round bruised hail spot. [4] Inspectors use the same 10x10 ft
     test-square method as hail, but count lifted/missing shingles per square instead of hail hits. [4]
   - Wind claims are usually **partial** (one slope, the side the wind came from) - document and
     photograph *that slope specifically*, not the whole roof, and say so plainly to the adjuster. [3]
   - If a storm brought both hail and wind, file one claim but **document each peril separately** with
     photos sorted by damage type - carriers sometimes lump it all as the cheaper peril to apply one
     deductible. [4] (This is about documentation, not negotiating the number - stays inside the
     legal line: photograph, measure, point to the damage, let the homeowner and adjuster settle it.)
   - Fallen-tree claims: this is homeowner-covered "if a covered peril (windstorm, etc.) knocked the
     tree onto the house" - not tree health. [5] Tarp-and-document first (FilthE already knows
     tarping matters for hail; same move here), then normal claim path - no different licensing or
     process for HMP than a hail claim. [5]

4. **Commercial/apartment: this is a relationship sale on a fixed calendar, not a knock list** -
   Effort: M, Owner: FilthE (with Cowork's commercial-scout keeping the contact list warm).
   Property managers plan roof CapEx on a yearly budget cycle: **most ownership groups want finalized
   capital numbers by Oct 15-Nov 30 for the following year**, meaning property managers are gathering
   roof condition data and contractor estimates in Sept-Oct. [6] That means: **the next 4-6 weeks
   (right now, late Sept) is the actual window** to reach out to HMP's known apartment/commercial
   targets offering a free roof condition inspection + written estimate they can hand up for next
   year's budget - not a cold pitch, a "help you build your Nov budget number" pitch. This is a
   scheduling insight the `calltoday` tool and commercial-scout should both know.
   Getting onto a bid list long-term comes down to 3 things every source agrees on: relevant
   experience/references (roof type, building count, on-schedule history), being reachable when RFPs
   go out (3-5 contractors typically get invited per project) [7], and being the contractor a property
   manager already trusts on a smaller job first. [7][8] There's no shortcut list-buying move here -
   it's slow trust-building, which fits HMP's current sub-for-VTR/Nastase relationship model better
   than solo cold outreach right now.

5. **TPO vs EPDM - what to know before bidding a flat commercial roof** - Effort: S (reading), Owner:
   FilthE.
   TPO: white/reflective, heat-welded seams, 20-25 yr life, best where cooling costs matter (most
   apartment/commercial roofs want this look now). EPDM: black rubber, glued/taped seams, 20-30 yr
   life, cheaper per square foot, holds up better in colder climates (matters for Nebraska winters -
   worth asking a supplier which one they stock more of locally). [9][10] HMP doesn't need to pick a
   side - just be able to explain the tradeoff to a property manager in one sentence and ask which
   membrane the existing roof already uses (matching the existing system is almost always cheaper
   than switching).

## Plain lines for FilthE
- Wind damage is a real second lead source and the engine already has the data (`wind_events`) - it
  just doesn't score it or show it on the map yet. That's a build task now on the board.
- Wind damage looks different than hail: creased or missing shingles on one side of the roof (the
  side the wind hit), not the round bruises hail leaves all over. Document that one slope carefully.
- If a tree came down in a storm and hit a roof, that's usually a normal covered claim, same steps as
  hail - tarp it, document it, file it. Nothing new to learn there legally.
- Apartments and commercial buildings buy roofs on a yearly budget, and **right now (late Sept-Oct)
  is when property managers are building next year's numbers** - that's the window to call them with
  a free inspection offer, not just anytime.
- TPO (white, newer, energy-savings pitch) and EPDM (black rubber, cheaper, older) are the two
  membranes you'll run into on flat roofs - you don't need to pick a favorite, just ask what's already
  up there and match it.

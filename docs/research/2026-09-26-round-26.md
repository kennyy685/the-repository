**Summary:** Good news, no new build needed. Digging into the actual code turned up that **both of this
round's topics are already done**. `hailhunter/wind.py` (T116-118 work, already merged and tested) already
detects tree/limb damage from LSR remark text (`is_trees`), extracts wind direction from remark words when
present (`wind_dir`), and both flow into `hud.json`'s `wind_events[]` as `trees_down`, `tree_sample`, and
`wind_dir` - confirmed by reading the code and running `hh.py selftest` (282 tests pass, including
`test_wind_zones.py`'s tree/direction tests). The LSR feed itself has no dedicated "tree report" type or
wind-direction field (NWS doesn't publish either) - `wind.py`'s code comments already document that limit
exactly. Nothing here needs a build task; it needs the backlog and board marked done, and one follow-up:
confirm Cowork's command center map (which HMP doesn't own the source for) actually displays `trees_down`/
`wind_dir` in its wind layer, since the data existing in hud.json doesn't guarantee the map surfaces it.
Statute check: search-engine summaries now include what look like direct quotes of 25-205 ("...an action
upon a specialty, or any agreement, contract, or promise in writing... can only be brought within five
years") and 44-357 (bars insurers from shortening the state's regular limitations period in a policy).
This matches round 25's inferred 5-year claim-lawsuit runway - still flagged unverified until fetched
directly, but no longer just an inference from commentary.

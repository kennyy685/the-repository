## Findings, most serious first
1. **HIGH** `pages/hub/scene.js:2298` (`catNeedsScan`): the no-nag key is `id|(a.since||a.seq)` and `a.since` = the agent doc's `at` (crew-hq.html:1276). A robot that re-posts the SAME question (still waiting, new `at`) is a "new need" to the cat. The page itself treats that as one need (`qidOf` = agent + hash of the normalized ask, crew-hq.html:1243). **Evidence:** harness, builder set to waiting (ask "Ship v28.1 to the hub today?"), play started and ended (12-17 s), then only `at` bumped: cat played with builder AGAIN (`with` samples: builder, null, builder, null = 2 plays). Fix: `const key = id + '|' + String(a.ask || a.doing || '').toLowerCase().replace(/[^a-z0-9]+/g, ' ').trim();`. Test case: same `ask`, new `at`, still waiting must give plays == 1; a different `ask` after an answer must give a new play.
2. **MEDIUM** `pages/hub/scene.js:2300`: `CAT.armed` turns true after 4 s of scene time, not after data has loaded. If the agents snapshot lands after that (slow runtime; `use('db')` may take up to 15 s), every robot that was already waiting is "new" and the cat plays with up to 3 of them on page load, which is the case the comment says never happens. (Static read, agrees with the automated code review; I could not reproduce the 4-15 s window here because swiftshader runs the scene at ~0.2x speed.) Fix: page sets `HUB.loaded = true` after the first agents + answers + board snapshots; scene only counts `armT` once `HUB.loaded` (or `HUB.needs.v > 0`).
3. **MEDIUM** `pages/crew-hq.html:2482`: health line pairs the age of the OLDEST waiting item with the name of `old[0]`, but `needItems()` sorts by holds, bot, runs, then oldest, so `old[0]` is not the oldest. Result: "Waiting on you 9h . Builder" when Designer has waited 9 h. It also goes onto the 3D table. Seen in my Ledger shot ("Waiting on you 3h . SMUIPO (King)"). Fix: `const o0 = old.reduce((m, i) => i.at < m.at ? i : m); ... 'Waiting on you ' + ageShort(o0.at) + ' . ' + o0.who`.
4. **MEDIUM** `pages/crew-hq.html:2469`: "Shipped this week" (Observatory card and table) over-counts. Run on 12 plausible lines: it counted "QA PASS: ready to publish", "Ready to publish v28.1 once you say yes", "Will publish after QA", "publish held for your OK", "Nothing shipped yet this week", "No publish until FilthE approves", "checks passed; awaiting publish", "the page is live, ok" (8 false positives). Fix: past tense only and a wider negative: `SHIP_RX = /\b(published|went live|is now live|shipped|merged)\b/i`, `NOT_SHIP_RX = /\b(not|never|no|nothing|before|until|waiting|awaiting|ready to|will|to be|held|hold|pending)\b[^.]{0,24}\b(publish|ship|live|merge)/i`. Test: the 8 lines above must not count; "Published hub v28.0 to the same URL" and "Engine PR merged into main" must.

### Low (non-blocking)
5. `pages/crew-hq.html:2558` (`applyCat`): turning the cat off while in the Y view leaves `HUB.cam === 'cat'` (verified); the scene falls back to Whole but the camera buttons/More menu stay on a view that is no longer built. Fix: `if (!catPref.on && cam === 'cat') setCam(catPrevCam || 'all');`.
6. `pages/crew-hq.html:2446`: Make it yours "Reset" resets look/colors/name but not the cat (name, coat, on/off). Either also `catPref = Object.assign({}, CAT_DEF); applyCat(true); renderCatMine();` or label the block "not reset".
7. `pages/hub/scene.js:2333`: contract says a play lasts max 25 s; the code caps the play at 12-17 s after arrival plus a 40 s failsafe from the start (a long walk can run past 25 s). Use `CAT.playEnd = Math.min(now + 12000 + rnd*5000, CAT.playFrom + 25e3)` and a 25 s failsafe.
